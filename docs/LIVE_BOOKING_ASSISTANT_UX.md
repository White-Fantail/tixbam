# TixBam 실전 예매 도우미 — 사용자 중심 UX (2026-10)

## 목적

사용자가 자동화 엔진을 이해하지 않아도 **공식 예매창에서 실제로 다음에 해야 할 행동**을 파악하게 한다. 좌석의 질보다 빠른 1장 확보가 우선인 계획은 해당 목표를 안내하지만, 사용자가 지정한 매수·예산·위험 조건을 임의로 변경하지 않는다.

## 기본 화면

1. 상단 4단계 진행 안내: **접속·로그인 → 대기·입장 → 좌석 선택 → 주문·결과 확인**. 이것은 예매처가 증명한 성공 상태가 아니라 사용자 단계 또는 안전한 참고 안내다.
2. 현재 상태에 대한 한 문장 설명과 **가장 중요한 다음 동작 버튼**을 보여준다.
3. 실제 예매 계획의 매수·예산·대안 허용 여부를 짧게 보여준다.
4. 좌석 선택 단계에서 AI가 생성한 후보가 있다면 희망 순서 및 대안을 표시한다. 이것은 화면상 후보 순위이며 실재고·실가격·공식 좌석 보류 증거가 아니다.
5. 화면 분석·좌표 표시·사용자 승인 1회 클릭은 **화면 분석 · 좌석 도움**을 선택했을 때만 펼친다.
6. 단계 수동 수정, Copilot 세션 원인/횟수/P95, 좌석 규정, 기타 진단 항목은 기본적으로 접어 놓는다.

## 각 단계의 동작

| 화면 | 주 동작 | 보호 장치 |
|---|---|---|
| 아직 창이 없음 | 공식 예매 사이트 열기 | 예매 계획에 등록된 URL 사용 |
| 공연·로그인 | 공식 창으로 이동하여 공연·회차·로그인 확인 | 로그인/인증 화면 캡처·클릭 차단, 호스트 자동 추가 금지 |
| 대기·대기열 | 공식 대기 창 유지 | 자동 새로고침/대기열 우회 없음 |
| 좌석 선택 | 화면 분석·버튼 위치 보기 또는 공식 창으로 이동 | 사용자 동의가 필요한 AI 스크린샷 전송, 일회성 승인 클릭만 기존 검증과 함께 허용 |
| 충돌·매진 힌트 | 공식 화면의 다른 승인된 후보 직접 확인 | 같은 좌석 무한 재시도 금지 |
| 장바구니·결제 | 공식 사이트의 공연·매수·좌석·총액·잔여 시간 확인 | 화면 진입만으로 보류·구매 완료 판단 금지 |
| 결과 확인 | 공식 영수증·구매 내역 확인 | 결과 미확인 결제 자동 재시도 금지 |

NOL에서 `accounts.yanolja.com` 같은 로그인으로 보이는 호스트는 **로그인 필요 화면**으로 표시할 수 있지만, 해당 호스트를 예매처가 허용한 자동화 대상이라고 간주하지 않는다. 공식 도메인 관계 및 허용 범위는 별도 검증이 필요하다.

## 신뢰 경계

- `bookingGuide`는 **화면에 표시할 안내만** 계산한다. `onPhase`, `copilotAdvanceResume`, 네이티브 클릭이나 결제를 자동 실행하지 않는다.
- AI의 `providerStep`은 로그인·결제·충돌처럼 안전한 쪽으로 유도하는 **경고**에만 사용한다. AI 관측만으로 공식 예약 단계를 앞당기지 않는다.
- 사용자 단계 변경은 실제 공식 화면 확인 후 사용자가 수행하며, 선택 화면으로의 전환도 명시적으로 확인한다.
- 기존 `LiveCopilot` 서버/메인 프로세스 제한(공식 호스트, 단계, 중복 클릭, 결제 보호)은 변경하지 않는다.

## 검증

```bash
git switch dev
git pull --ff-only origin dev
npm run verify:nol
npm run build:desktop
```

Electron UI 회귀에서는 기본 간편 안내, 기술 진단 접힘, 화면 분석 도구 열기, NOL 로그인 주소 진입 시 캡처 차단, 좌석 후보 표시, 대기/결제 단계 차단, 사용자 재개/중지를 확인한다. **합성·오프라인 통과는 실제 NOL 좌석 확보 성공률을 증명하지 않는다.**
