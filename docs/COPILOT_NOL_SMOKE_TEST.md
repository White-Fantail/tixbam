# NOL 실전 코파일럿 스모크 테스트 (개발용)

> 범위: 화면 캡처, 버튼 위치 제안, 표시, **사용자가 확인·승인한 1회 클릭**까지.
> 실제 좌석 확보·장바구니·결제 완료 또는 AI 자동 예매의 검증이 아니다.
> 로그인·대기열·CAPTCHA·결제·은행 인증은 코파일럿이 수행하지 않는다.

## 사전 준비

1. 최신 `dev` 브랜치에서 `npm install`, `npm run dev`로 **Electron 앱**을 실행한다. 브라우저의 Vite 미리보기(`npm run dev:web`)에는 로컬 캡처 브리지가 없다.
2. NOL 이벤트의 **Booking Plan**을 선택하고, 공식 티켓 사이트를 **그 계획에서** 연다. 단순한 Add-on 바로가기 창은 계획과 연결되지 않으므로 코파일럿 대상이 아니다.
3. AI 제안을 시험한다면 TIXBAM 계정으로 로그인한다. Railway API에는 `OPENROUTER_API_KEY`가 있어야 하며, Admin → AI Models에서 `copilot_vision`을 vision 지원 모델로 활성화해야 한다. AI가 꺼져 있어도 수동 위치 지정/표시/1회 클릭 테스트는 가능하다.
4. 무관한 공연의 실제 결제까지 진행하지 않는다. 장바구니·결제 성공을 TIXBAM이 판정하지 않는다는 점을 확인한다.

## A. 공연 상세/예약 시작 화면 (스크린샷에 보이는 NOL 화면)

1. '현재 단계'는 **준비 중**으로 유지한다.
2. **예매 페이지 연결 확인 (읽기 전용)**을 누르면 NOL 공식 화면 캡처가 표시되어야 한다.
3. 캡처에서 '예매하기' 버튼을 마우스로 지정하고 **사이트에 위치 표시**를 누른다. 공식 창에 표시만 생기고 클릭은 일어나지 않아야 한다.
4. AI 설정이 준비됐다면 **AI로 버튼 위치 찾기 (이미지 전송 동의)**를 누른다. 개인 정보가 없는지 확인 후 1회 동의한다. 이 단계의 AI는 다음 단계로 넘어가는 `continue` 후보만 제안한다. '확인 후 1회 클릭' 버튼은 표시되지 않아야 한다.
5. 실제 **예매하기**는 공식 NOL 창에서 사용자가 직접 누른다.

> 주의: 개발 데스크톱 앱은 기본적으로 운영 Railway API를 이용한다. `dev` API 코드의 준비 화면용 `stage` 필드가 **운영 서버에 아직 배포되지 않았다면** 준비 화면의 AI 분석에서 HTTP 422가 나타날 수 있다. 이 경우 화면 캡처와 수동 위치 표시는 정상 시험할 수 있고, 실제 좌석 선택 화면의 기존 Vision 요청은 이전 API와 호환된다. API 변경 배포 전에는 준비 화면 AI 성공을 주장하지 않는다.

## B. 실제 티켓/좌석 선택 단계

1. 사이트에서 로그인·대기열·보안 확인은 직접 처리한다.
2. 좌석 선택이 **실제로 보일 때만** TIXBAM의 **티켓 선택 단계로 전환**을 누르거나 우측 '현재 단계'에서 **티켓 선택 중**을 선택한다. 팝업으로 열린 경우 '예매처 팝업' 목록의 **코파일럿에서 사용**을 눌러 해당 팝업을 대상으로 지정한다.
3. **실제 예매 화면 가져오기**를 눌러 해당 공식 창의 이미지가 표시되는지 확인한다.
4. 사용자가 직접 버튼 위치를 선택하거나, 계정/관리자 설정이 끝났다면 AI 버튼 후보를 요청한다. AI 제안은 사용자가 검토하고 선택해야 한다.
5. **사이트에 위치 표시**가 정확한 좌표에 뜨는지 확인한다. 사이트 버튼 자체는 클릭되지 않아야 한다.
6. 구입과 무관한 안전한 선택 요소(예: 좌석 목록 내 선택 가능한 항목)를 지정하여 **확인 후 1회 클릭**을 사용자가 명시적으로 승인하면, 정확히 1회 클릭되어야 한다. 다시 실행하려면 새로운 캡처와 승인이 필요하다.
7. 클릭 대상 근처가 바뀌거나, 사이트가 이동하거나, 화면 크기가 바뀌면 과거 캡처의 클릭을 거부해야 한다. 다른 위치의 시계/배너만 바뀌는 경우에는 클릭 대상 영역 검증이 유지된다.
8. CAPTCHA·로그인·결제 URL 또는 해당 단계를 선택한 상태에서는 캡처/클릭이 거부되어야 한다.

## 검증 및 알려진 제한

- 빠른 자동 회귀: `npm run test:copilot` (NOL/Copilot만 빠르게 점검), `npm test` (전체 Electron 체크), `npm run check`, `npm run build:desktop`.
- 모의 테스트는 네트워크 및 실제 티켓 사이트와 상호작용하지 않는다. 운영 NOL의 팝업 호스트, 렌더링, 버튼 오버레이의 macOS 정확도는 사용자의 실제 화면에서 별도로 확인해야 한다.
- 서로 다른 예매처/로그인/결제 도메인으로 이동한 팝업은 공급자 허용 도메인이 검증될 때까지 안내되지 않는다. 임의의 도메인을 자동으로 허용하지 않는다.
- 화면 안의 버튼은 실제 재고/가격/장바구니 상태를 증명하지 않는다. 좌석·결제·영수증 결과는 공식 사이트를 직접 확인한다.


## 사전 승인 자동화 검증 (현재 dev)

1. 내 티켓팅 → 해당 공연 → **코파일럿 사전 승인** 설정으로 이동한다.
2. NOL에서는 '자동 클릭' 옵션이 비활성화되고 **예매처 정책상 제한** 이유가 표시되어야 한다. Cityline/Ticketmaster/AXS도 동일하다. YES24/KKTIX는 **허용 검증 전**이라서 비활성화된다. Live Nation은 별도 예매처를 지정하는 이벤트 사이트라서 비활성화된다.
3. **자동 화면 인식 및 버튼 안내**를 선택하고, 허용 작업을 정하고, 캡처 전송 동의를 체크한 뒤 설정을 저장한다. 일반 설정에 저장한 기본값은 공연별 설정이 없을 때 적용된다.
4. 공연의 **Start live booking**을 누르면 한 번의 사전 승인 확인 창이 나타나야 한다. 확인하면 공식 예매 창이 열리고, 안전한 공식 예매 단계일 때 캡처·AI 안내를 자동 시도한다. 로그인하지 않았거나 API의 Copilot Vision 기능이 꺼져 있으면 안내를 일시 중지하고 원인을 표시해야 한다.
5. **진행 중인 예매**에서 사전 승인 상태 및 분석 횟수(최대 5회)를 보고, **자동 화면 분석 즉시 중지**를 누르면 이후 자동 분석을 진행하지 않아야 한다.
6. 예매 창 내 페이지 이동에도 허용된 범위에서 다시 관찰한다. 짧은 화면 변경은 합쳐서 처리한다. 대기열/로그인/결제 화면에서는 분석·클릭을 차단한다.
7. 글로벌 저장값이 `authorized`더라도 NOL 공연에서 실제 적용 모드는 **화면 안내만**이어야 한다. 기본값 또는 외부에서 조작한 설정이 예매처의 정책을 덮어쓸 수 없다.

### 범위 및 검증 제한

등록된 애드온에는 현재 **검증된 자동 좌석 클릭 실행기**가 없다. 따라서 이 변경은 안전한 자동 화면 관찰과 사전 승인 관리, 그리고 정책 기반으로 비활성화된 자동 클릭 설정의 시험을 가능하게 한다. NOL 자동 좌석 확보나 결제 자동화가 작동한다고 주장하지 않는다. `node --test apps/desktop/electron/copilot.advance.test.cjs`와 `npm run check`, `npm test` 실행 후 macOS에서 실제 사이트 UI 위치 표시를 확인해야 한다.


## 로컬 개발자 단일 클릭 테스트 (정책 우회 진단용)

이 기능은 일반 사용자의 "자동 클릭" 옵션을 열지 않습니다. 운영/패키징 빌드에서는 Electron 메인 프로세스가 개발자 기능을 완전히 거부합니다. 개발자 실행기능은 **로컬 Electron 실행 + 명시적 CLI 플래그** 두 조건이 모두 맞아야 열립니다.

1. 프로젝트 루트에서 `npm ci` (최초 1회) 후 **`npm run dev:copilot`**으로 앱을 실행합니다. 일반 `npm run dev`나 패키징된 앱에는 이 기능이 없습니다.
2. **내 티켓팅 → NOL 공연 예매 계획 → 코파일럿 사전 승인**에서 **이 공연만 별도 설정**을 체크합니다.
3. 진행 방식은 **자동 화면 인식 및 버튼 안내**를 선택합니다. 일반 **자동 클릭** 옵션은 NOL 정책에 따라 계속 비활성화되어 있어야 합니다.
4. 실험할 항목(예: **좌석 / 구역 선택**)을 선택하고 스크린샷 공유 동의 후 **개발자 클릭 진단 (로컬 실행 전용)**을 체크해 저장합니다. 전역 설정에는 이 진단을 저장할 수 없습니다.
5. **Start live booking**을 눌러, `개발자 진단: 실제 화면에서 자동 클릭 최대 1회`라는 경고를 확인하고 승인합니다.
6. NOL에서 로그인·CAPTCHA·대기열은 수동으로 진행합니다. **좌석 선택 화면에 실제로 도달했을 때만** TixBam에서 현재 단계를 **티켓 선택 중**으로 변경합니다.
7. 분석할 화면에 요청한 좌석/구역 버튼이 명확히 보이고 AI 확신도가 95% 이상이라면 Electron이 해당 좌표로 실제 `mouseDown` + `mouseUp` 1쌍을 보냅니다. 반드시 공식 사이트에서 실제로 버튼이 반응했는지 확인합니다.
8. 첫 유효 클릭을 보내면 진단 세션은 자동 종료됩니다. 성공 알림은 **좌표 입력 이벤트 발송**만 뜻하며, 좌석 확보·장바구니·결제 성공을 뜻하지 않습니다. 중지 버튼을 누르거나 앱을 닫아도 사전 승인은 취소됩니다.

**주의:** 실제 사이트의 이용약관상 자동화가 제한될 수 있습니다. 진단 기능은 이용약관상 사용 허가를 부여하지 않습니다. 테스트 계정/허가된 환경을 우선 사용하세요. 이 기능은 사이트의 자동화 탐지·대기열·CAPTCHA·결제 제한을 우회하지 않으며, 다른 예매처로 자동 확장되지 않습니다.

### 음성/코드 회귀 기준

- 앱 패키징 후: 개발자 기능 미노출, IPC로 `developmentOverride:true`를 전송해도 거부
- 로컬 개발 + 일반 `npm run dev`: 동일하게 거부
- 로컬 개발 + `npm run dev:copilot`: 사전 승인, 실제 좌석 선택 단계 및 신뢰도 조건을 충족할 때 1회만 클릭
- 이벤트 상세(준비 중), 로그인, 대기열, 결제, 낮은 신뢰도, 기존 캡처 만료, 변경된 버튼, 중단 중 AI 응답: 클릭 0회
- 두 번째 클릭: 별도 예매 계획 승인 과정을 새로 시작하기 전까지 불가능

오프라인 자동 검증: `npm run test:copilot`, `npm run check`, `npm test`.


### 업데이트: 개발자 모드에서는 제한된 애드온의 자동 클릭 옵션도 설정 가능

`npm run dev:copilot`으로 시작하면 **내 티켓팅 → 예매 계획 → 코파일럿 사전 승인**에서 NOL, Cityline 등 제한된 티켓팅 애드온도 **자동 클릭 테스트 (개발자 모드 · 최대 1회)** 항목을 선택할 수 있습니다. 예매 계획별 **별도 설정**을 먼저 활성화하세요. 자동 클릭 모드를 선택하면 아래의 개발자 단일 클릭 진단이 자동으로 선택되므로 별도 중복 체크는 필요하지 않습니다. 회차·가격 등급·매수·좌석 중 하나 이상의 대상과 스크린샷 동의를 선택하고 설정을 저장합니다.

예매 창 열기 직전에 개발자 진단(실제 입력 최대 1회)을 다시 승인합니다. Electron 호스트는 Dev CLI 플래그, 비패키징 빌드, 실 예매처 애드온, 계획별 승인, 단계, 화면 일치, 신뢰도를 재검증합니다. 일반 `npm run dev` 및 패키징 빌드는 자동 클릭 모드를 계속 비활성화하고, 기존에 Dev로 저장한 계획의 자동 실행 권한도 부여하지 않습니다. 일반 설정의 전역 승인만으로는 Dev 예외가 활성화되지 않습니다.

**현재 실제 실행기 제한:** 자동 클릭 테스트 모드에서도 실사이트에서 보내는 이벤트는 티켓 선택 단계의 최대 1회 클릭입니다. 예매 진입(Continue), 결제, CAPTCHA, 대기열, 로그인은 자동 클릭하지 않습니다. Cityline의 별도 좌석 선택 팝업 및 실제 페이지 UI는 검증되지 않았습니다. 본 개발자 진단은 사이트 이용약관에 대한 허가를 의미하지 않습니다.
